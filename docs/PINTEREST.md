# OmniSocial Pinterest Integration

This guide documents the Phase 27 Pinterest integration currently implemented in OmniSocial.

## Current capability

The first Pinterest integration supports:

- OAuth 2.0 account connection
- Account discovery
- Token storage and refresh
- One-image Pin publishing
- Board discovery
- Automatic creation of an `OmniSocial` board when the connected account has no boards
- Immediate publishing through the existing publishing worker
- Scheduled publishing through the existing scheduler/worker
- Platform-specific media validation
- Post History status/result handling

Pinterest's current API supports organic image and video Pins. The current OmniSocial integration intentionally starts with image Pins because Pinterest video Pins require an asynchronous media-upload registration flow plus a cover image. Video support should be added only when that flow can be implemented and tested reliably. citeturn1search0turn1search5

## 1. Create the Pinterest developer app

1. Open the Pinterest Developer Platform:
   - https://developers.pinterest.com/
2. Sign in with a Pinterest business/developer account.
3. Open **My apps**.
4. Create a new app or open the existing OmniSocial app.
5. Ensure the app is approved for Pinterest API access. Pinterest documents Trial and Standard access tiers; applications intended for real customer use should use the access tier appropriate for the production use case. citeturn0search12turn0search7
6. Find the app ID and app secret.

Pinterest's OAuth documentation identifies the app ID/client secret and registered redirect URI as prerequisites for authorization-code OAuth. citeturn0search2

## 2. Configure the redirect URI

OmniSocial uses the common callback:

```text
https://YOUR-DOMAIN/api/social/oauth/callback
```

For local development:

```text
http://localhost:3000/api/social/oauth/callback
```

The redirect URI supplied to Pinterest must exactly match the URI registered for the app. citeturn0search2

## 3. Configure OmniSocial environment variables

Add these server-side variables:

```env
PINTEREST_CLIENT_ID=your_pinterest_app_id
PINTEREST_CLIENT_SECRET=your_pinterest_app_secret
PINTEREST_OAUTH_SCOPES=user_accounts:read boards:read boards:write pins:read pins:write
```

Never expose `PINTEREST_CLIENT_SECRET` to the browser and never commit it to Git.

The requested scopes allow OmniSocial to read the connected account, read/create boards as needed, and create/read Pins. Pinterest recommends requesting only the scopes actually required by the application. citeturn0search2

## 4. OAuth flow

The OmniSocial flow is:

```text
User clicks Connect Pinterest
        ↓
OmniSocial creates OAuth state
        ↓
Pinterest OAuth authorization page
        ↓
User approves access
        ↓
Pinterest redirects to
/api/social/oauth/callback
        ↓
OmniSocial exchanges authorization code
        ↓
Access + refresh tokens are encrypted and stored
        ↓
Pinterest user profile is loaded
        ↓
Pinterest account is associated with the selected Publishing User
        ↓
Account appears as Connected
```

Pinterest's documented authorization-code flow follows the same redirect → authorization code → token exchange pattern. Pinterest also supports refresh tokens for continued access. citeturn0search2turn0search10

## 5. Board handling

Pinterest Pins are saved to boards. citeturn1search0turn1search5

OmniSocial does not require a separate board-management screen for the first integration.

When publishing:

1. OmniSocial checks the connected account metadata for a configured board.
2. If none is stored, it asks Pinterest for the user's first board.
3. If the user has a board, that board is used.
4. If the user has no board, OmniSocial creates a public `OmniSocial` board and uses it.
5. The Pin is created on that board.

This keeps the first publishing flow simple while preserving the existing Publishing User → Social Account architecture.

## 6. Create a Pinterest Pin

Current OmniSocial flow:

```text
Create Post
   ↓
Select Pinterest
   ↓
Select one image
   ↓
Enter post text
   ↓
Publish Now / Schedule
   ↓
Existing publishing worker
   ↓
Pinterest Create Pin API
   ↓
Pin ID returned
   ↓
Post History = Published
```

Pinterest's Create Pin API accepts an image URL media source for image Pins. citeturn1search0

The image therefore needs to be reachable by Pinterest from the media URL generated by OmniSocial's existing media-storage flow.

## 7. Media validation

Current Pinterest capability in OmniSocial:

| Media | Support |
|---|---|
| JPEG | ✅ |
| PNG | ✅ |
| WebP | ✅ |
| Multiple images in one Pinterest Pin | ❌ |
| Video Pin | ❌ in current OmniSocial integration |
| Text-only Pin | ❌ |

If a user selects Pinterest and uploads a video, OmniSocial should report a destination-specific compatibility message instead of a generic provider failure.

Example:

> OmniSocial's current Pinterest integration supports image Pins only. Remove the video or deselect Pinterest.

## 8. Token refresh

Pinterest authorization-code tokens include refresh tokens. The OmniSocial provider refreshes an expired access token through Pinterest's OAuth token endpoint and stores the refreshed encrypted access token. Pinterest currently documents continuous refresh-token behavior for newer apps. citeturn0search2

## 9. Production testing checklist

After adding the Pinterest credentials to the deployment environment:

- [ ] Open Connect Accounts.
- [ ] Select a Publishing User.
- [ ] Confirm Pinterest shows **Ready to connect**.
- [ ] Click **Connect Pinterest**.
- [ ] Complete Pinterest OAuth.
- [ ] Confirm Pinterest appears as **Connected**.
- [ ] Create a post with one JPEG/PNG/WebP image.
- [ ] Publish immediately.
- [ ] Confirm the Pin appears on Pinterest.
- [ ] Confirm Post History contains the Pinterest platform and returned Pin ID.
- [ ] Schedule a Pinterest image post.
- [ ] Confirm the scheduled worker publishes it.
- [ ] Test a video and confirm the destination-specific validation message appears.
- [ ] If the Pinterest account has no boards, verify OmniSocial can create/use the `OmniSocial` board.
